## A1: baseline on David's computer (Windows 11, Python 3.12.10, uv 0.12.17)

Branch `release/v4.1.0` created from `handoff/v4.1.0-base` (5eeada3). `uv sync --dev` clean.
The handoff baseline was measured on Linux; the suite did not collect on Windows, so the
environment was fixed first (all test-only or portability-only, no behaviour change):

- `extensions/feature_workflow/{coordinator,run_state}.py` imported `fcntl` (POSIX only) and
  used `os.O_DIRECTORY` for the directory fsync. Added `extensions/feature_workflow/_filelock.py`
  (fcntl on POSIX, msvcrt on Windows) with `tests/test_feature_workflow_filelock.py` (2 tests);
  the directory fsync is skipped where the flag does not exist.
- `tests/conftest.py`: Windows-only patch for a CPython quirk — cancelling a task while it is
  inside `create_subprocess_exec` leaves the transport's `_wait()` unresolved forever, which
  hung pytest-asyncio's loop teardown (first seen in `test_task_loop_cog.py`).
- `tests/test_codex_runner.py`: the interruptible fake process now honours `terminate()`,
  which is what `CodexRunner.interrupt()` calls on Windows (the test hung otherwise).
- Path-separator-only assertion fixes: `test_feature_workflow.py` (manifest paths are POSIX by
  contract → `as_posix()`), `test_project_catalog.py` (real tmp roots use native `PurePath`;
  the two symlink tests skip when the OS refuses symlinks), `test_collision_detection.py`,
  `test_transcript_lookup.py`; `render_preview.preview_name()` now returns a POSIX name on
  every OS (its docstring contract).
- Linux ops-script tests (`test_cleanup_worktrees_script.py`, `test_deploy_drift_script.py`,
  `test_health_check_script.py`, `test_pre_start_script.py`) are `skipif(win32)`: they check
  executable bits and put bash-shebang stubs on PATH.
- Machine setup: installed `uv`, set a global git identity (tests commit inside fresh clones).
